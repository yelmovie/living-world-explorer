P3에서 렌더러·드래그·저장·대체 화면의 기술 위험을 일찍 확인한다. 이때 관리자 예시 자료를 기능 개발에 사용할 수 있지만 실제 학습 완료로 인정하지 않는다.

P1부터 사용 가능한 대표 흐름을 만들고 P5에서 전체 MVP를 연결한다. 날짜·개발 일수는 인력과 에셋 준비 상태가 없으므로 확정하지 않는다.

v1.1 설계 우선순위는 M4 시간 탐색과 M5 실행 비교다. 구현 의존성상 P0/P1을 먼저 만들고, P3에서 실행 이력을 검증한다. P4에서는 M4 시점 쌍/정렬을 먼저 구현하고 이를 M2 재생 비교에 공통 활용한다. 구현 순서와 학생의 플레이 순서(M1→M5)는 구분한다.

## 2 기능 개발과 학생용 공개의 차이

기능 개발은 임시 형상·설명용 도식으로 진행할 수 있다. 학생용 공개는 과학 자료·사례·사용 권한·목표 기기 확인을 요구한다. 다음 항목을 구현 완료와 혼동하지 않는다.

| 항목 | 현재 상태 | 해결할 단계 |
|---|---|---|
| 2.5D 지도·걷기 프레임 | 미제작 | P2 |
| 과학 관찰 이미지와 특징 영역 | 미확보·미검수 | P1부터 준비, P6까지 검수 |
| M4 동일 표본 4시점·유효 비교 쌍·변화 영역 | 미확보·미검수 | P4 구현 전 후보 검토, P6 공개 전 검수 |
| M2 같은 개체의 재생 자료·M3 주장/원문 관계 | 미확보·미검수 | P4 |
| 생활 사건 4종 중 원생생물 사례의 구체적 대상 | 교과 검수 필요 | P4 전에 결정 |
| GLB 7종과 레버 pivot/포트 anchor | 미제작 | P3 기술 검증 후 교체 |
| 3D 앞쪽 장치가 없는 배경 | 미제작 | P3~P5 |
| 로컬 저장·PNG·인쇄의 실제 기기 동작 | 미검증 | P6 |
| 외부 Science World 연동 | MVP 제외 | 후속 요청 시 |

## 3 핵심 검증 시나리오

### 일반 완주

새 연구 → 지도에서 의뢰 → M1~M5 순차 수행 → 각 장 완료 후 지도 변화 → 모아에게 실제 기록 5종 보고 → 코어 직접 연결/가동 → 결과 편집 → PNG 저장·인증서 인쇄.

중간의 다음 버튼, 완료 화면 직접 URL, 새로고침만으로 조건을 우회할 수 없어야 한다.

### 관찰과 판정

- 초점이 맞지 않거나 특징이 시야 밖인 사진은 유효 관찰 근거가 되지 않는다.
- 힌트·정지 관찰 보조를 사용해도 필요한 관찰·비교 결과를 갖추면 완료할 수 있다.
- 추측/무관 자료 3개로 세균 미션을 완료할 수 없다.
- 도움/문제 선택만으로 생활 영향 미션을 완료할 수 없다.
- 모듈 자리가 맞아도 생물/작용·흐름이 틀리면 RUN 성공이 되지 않는다.
- 처음 RUN에 성공한 학생에게 재시도를 강제하지 않는다.

### 전체 해금

미완료 연구에서 스위치 한 번 → 모든 15 route 진입 → 선행 기록이 없는 최종 화면도 예시로 확인 → 예시 완료/내보내기 표시 → 스위치 끄기 → 기존 일반 진도와 실제 기록이 그대로 복원.

일반 완료 평가에 origin=demo 또는 다른 attempt의 연구 기록을 넣으면 거부해야 한다.

### 저장과 복원

사진 촬영·주석·장치 초안·보고 확인 직후 새로고침 → 마지막 성공 저장 상태 복원. DB 차단·quota 초과 시 기록을 자동 삭제하지 않고 현재 작업과 저장 상태 안내 유지. 중복 레버 입력과 화면 재방문으로 완료 기록이 중복 생성되지 않음.

### 3D와 입력

조립 → 가동 → 지도 → 코어 화면을 반복 방문. UI 탭이 뒤의 3D 오브젝트를 움직이지 않음. 드래그 취소·모달 열기에서 원치 않는 배치가 확정되지 않음. WebGL 불가/컨텍스트 손실에서 같은 초안의 2D 작업대로 이어짐.

### 화면과 기기

1280×800·1024×768·1280×720에서 코너 아이콘, 주요 행동 버튼, 모달, 주석 도구가 잘리지 않음. 실제 CSS 터치 영역 48px, 손가락 옆 확대창·미세 조절, 큰 글씨와 키보드 초점, 소리 상태를 확인. Android Chrome·iPad Safari의 입력·저장·PNG/인쇄와 저사양 30fps 목표를 별도 확인.

## 4 테스트 수준

| 수준 | 대상 | 이유 |
|---|---|---|
| 단위 | 미션 판정기, 그래프, 출처/시도 구분, 최종 완료 멱등성 | 잘못된 학습 완료 방지 |
| 통합 | 사진과 상태 트랜잭션, 복원, 렌더러 전환 | 기록 손실과 상태 차이 방지 |
| 브라우저 | 일반 완주, 전체 해금, 3D 대체, 결과 저장 | 사용자가 실제 완료할 수 있는지 확인 |
| 수동/실기기 | 과학적 타당성, 터치, 가독성, 성능, 인쇄 | 자동 검증으로 확인할 수 없는 부분 |

단순 색·여백 변경에 구현을 그대로 베끼는 테스트를 추가하지 않는다. 관련 판정과 흐름을 우선 검증하고 변경·실패·미해결 위험이 있을 때만 범위를 넓힌다.

### v1.1 실패 경로 검증

- M1 기준 사진을 고정한 뒤 실시간 시야를 바꿔도 원본 주석이 움직이지 않는다.
- M2 카메라만 움직인 기록을 개체 이동으로 판정하지 않는다. 동일 프레임 A/B나 다른 track 조합은 거부한다.
- M3 근거 해제 후 이전의 ‘확인 가능’ 상태가 남지 않는다. 무관 자료를 사실과 불일치한다고 단정하지 않는다. 지원/불일치가 섞이면 원문 검토를 요구한다.
- M4 같은 표본의 서로 다른 유효 전후 조합들이 통과한다. 동일 사진·다른 표본·변화와 무관한 표시를 거부한다. 두 시점 사진만으로 사건 근거 2개를 채우지 못한다.
- M5 예상은 RUN 전에 해당 설계 버전에 연결한다. 예상이 틀려도 관찰 후 타당한 설명으로 완료할 수 있다. 성공 후 수정한 초안은 과거 성공으로 통과하지 않는다. 실행 중 새로고침은 중단 기록이며 성공을 생성하지 않는다.
- 모든 추가 기록에서 다른 attempt·demo·자료 버전 누락을 검사한다. 모달·pointercancel·WebGL 전환 후 초안과 비교 선택을 유지한다.
- 학생 파일럿에서 35~45분 목표와 ‘바꾼 것→발견한 변화→설명 근거’를 확인한다. 반복 읽기·이동을 줄여도 핵심 탐구는 유지한다. 파일럿 없이 학습 효과가 검증됐다고 보고하지 않는다.

## 6 다음 실행 단위

첫 구현은 **P0 공통 골격과 P1의 최소 관찰 흐름**이다. 이때 메인·지도 진입 틀, 공통 아이콘, 설정과 전체 해금, 저장, M1 초점/촬영/주석/연구 기록을 실제로 연결한다. 나머지 화면을 미완성 버튼으로만 채우고 전체 MVP 완료로 보고하지 않는다.

후속 작업의 진행 보고에는 구현 완료, 검증 완료, 임시 에셋, 미검증 기기를 구분해 적는다.
