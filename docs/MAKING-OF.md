## 1. 왜 만들었나요

이 단원의 성취기준은 세 가지예요.

- [4과12-01] 균류·원생생물·세균을 관찰하여 특징과 사는 곳을 설명할 수 있다.
- [4과12-02] 균류·원생생물·세균이 우리 생활에 미치는 영향을 조사하여 발표할 수 있다.
- [4과12-03] 우리 생활에 생명과학이 이용되는 사례를 소개하는 자료를 만들어 공유할 수 있다.

설계 문서(`docs/PRD.md`, `docs/TABLET_EXPLORATION.md`)에 적은 목표는 이래요.

- **정답 카드를 고르는 게임이 아니라, 화면을 조작한 결과가 관찰 자료로 남고 그 기록으로 설명하게 하기.** PRD에는 "화면의 조작 결과가 관찰 자료와 장치 상태에 반영되어야 한다"고 적었어요.
- **활동마다 같은 흐름 지키기.** 조작 → 변화 발견 → 근거 기록 → 설명 확인·수정 순서예요.
- **종이로는 하기 어려운 조작 넣기.** 현미경의 초점·밝기를 직접 맞추고, 움직이는 짚신벌레를 멈춰 두 순간을 비교하고, 같은 빵·낙엽의 관찰 순서를 앞뒤로 오가고, 직접 설계한 장치를 실행해 결과를 보는 활동이에요.
- **빠르기나 운으로 보상하지 않기.** 속도, 반복 클릭, 처음에 정답을 골랐는지로 보상하지 않아요. 틀린 예상도 감점하지 않아요. 제한 시간과 목숨도 넣지 않았어요.

이 설계가 실제 학습에 도움이 되는지는 아직 확인하지 않았어요. 학생 사용 관찰이 남아 있어요.

## 2. 무엇을 만들었나요

### 이야기

생명 코드 연구소의 BIO CORE에 데이터 연결 오류가 생겨서 숲과 연못의 관찰 기록이 뒤섞였어요. 모아 연구원과 길잡이 토끼 토토가 학생에게 도움을 청해요.

학생은 지도에서 다섯 연구 시설로 이동해 탐구하고, 자기가 남긴 연구 기록으로 시설을 하나씩 복구해요. 마지막에는 다섯 기록을 모아에게 보고하고, 학생이 직접 기록을 코어의 포트에 연결해서 가동해요. 자동 엔딩으로 넘어가지 않아요. 결과 화면에서는 학생이 고른 사례와 직접 쓴 문장으로 소개 카드(PNG)를 저장하고 인증서를 인쇄할 수 있어요.

### 다섯 연구 시설 × 탐구 4개

| 연구 시설 | 탐구 1~4 | 받는 기록 · 복구 |
|---|---|---|
| M1 균류 관찰 · 버섯숲 표본실 | 버섯과 곰팡이는 어디서 발견했을까요? / 버섯의 갓 아래를 자세히 살펴봐요 / 곰팡이에서 어떤 모양이 보이나요? / 새 표본의 관찰 노트를 완성해요 | 균류 관찰 패킷 · 표본실 조명 |
| M2 한 방울 탐구 · 연못 관찰소 | 연못의 물 한 방울을 준비해요 / 실처럼 이어진 해캄을 찾아요 / 짚신벌레의 두 순간을 비교해요 / 두 생물의 차이를 조사해요 | 한 방울 비교 기록 · 연못 관찰소 |
| M3 세균의 단서 · 자료 연구실 | 관찰과 추측이 섞인 자료실을 정리해요 / 어떤 자료로 세균의 특징을 설명할까요? / 사는 곳을 알려 주는 자료를 찾아요 / 새 자료를 보면 내 주장은 달라질까요? | 세균 증거 프로필 · 자료 통신망 |
| M4 생활 속 사건 · 생활마을 | 빵에서 어떤 변화가 보이나요? / 숲의 낙엽도 같은 방법으로 조사해요 / 우리 생활에 어떤 영향을 줄까요? / 다른 네 사건에도 적용해봐요 | 생활 영향 사건 보고서 · 생활마을 연구등 |
| M5 생명과학 작업실 · BIO 작업실 | 요구르트 설계도를 만들어 가동해요 / 이번에는 빵 반죽 설계에 도전해요 / 숲의 낙엽 처리 장치도 설계해봐요 / 내 생명과학 소개 카드를 만들어요 | 나만의 BIO 설계도 · BIO 작업실 전원 |

활동 내용은 `src/curriculum.ts`에, 보상은 `src/experience.ts`에 있어요. M1~M3는 [4과12-01], M4는 [4과12-02], M5는 [4과12-03]에 연결돼요.

### 조작의 종류

- **관찰:** 초점·밝기·확대·이동을 맞춰 촬영하고, 특징이 보이는 곳을 표시해요.
- **채집:** 스포이드로 연못 물 한 방울을 옮겨요.
- **추적·비교:** 움직임을 멈추고 같은 생물의 두 시점을 A/B로 고정해요.
- **시간 탐색:** 같은 빵·낙엽의 관찰 순서 1~4를 오가며 전후를 고정하고 변화한 곳을 표시해요.
- **분류·연결:** 자료를 열어 읽은 뒤 드래그하거나, 탭한 다음 대상을 눌러 연결해요. 읽지 않은 자료는 드래그되지 않아요.
- **주장 다시 보기:** 처음 생각 → 새 자료 두 개 → 주장과 근거 → 유지 또는 수정(M3-4).
- **조립·실행:** 재료 → 생물의 작용 → 결과를 배치·연결하고, 예상한 뒤 실행해서 결과와 비교해요.
- **소개:** 사례·생물의 작용·근거를 고르고 짧은 문장틀로 소개 카드를 만들어요. 글자 수는 채점하지 않아요.

드래그와 캔버스 조작에는 버튼으로 하는 대안이 있어요. 막히면 토토의 힌트를 열 수 있고, 근거가 부족하면 무엇을 더 하면 되는지 구체적으로 알려 줘요.

### 교사용 기능

설정에 학생용·교사용 가이드와 성취기준이 있어요. 교사용 도구의 '모든 단계 한 번에 열기'는 수업 시연용이에요. 시연 기록과 예시 기록은 학생 기록과 다른 공간에 저장되고, 다시 누르면 학생의 원래 진행으로 돌아가요. 공용 기기에서 쓸 때의 주의와 기록 초기화도 설정에 있어요.

## 3. 어떻게 만들었나요

### 설계를 바꾼 과정

- 2026-10-15~16에 설계 문서(PRD·TRD·인터랙션·에셋·구현 계획 v1.1)를 먼저 썼어요. 이때는 지도를 2.5D로, M5와 마지막 코어를 실제 3D로 계획했어요.
- 2026-10-18에 v1.2로 바꾸고 첫 구현을 했어요. 지도와 활동 장면을 2D Phaser 중심으로 정했어요. 이전 Three.js 코드는 보존만 하고 실행 경로에서는 쓰지 않아요.
- 첫 구현은 5개 장소 · 학습 활동 10개였고, 2026-10-24 최종점검 때는 20개 활동(5 × 4) 기준으로 검사했어요.

### 기술 구성

| 개발·빌드 | Vite 7, TypeScript 5.9 |
| 지도·숲 단서·채집·연결도·시간 탐색·조립·코어 | Phaser 3.90의 2D 장면 |

스테이지 모듈과 Phaser는 필요할 때 불러와요. 2026-10-25 기준 운영 주소에는 `c786b1b` 빌드가 올라가 있고, 그 뒤 수정은 아직 배포하지 않았어요.

### 그림 · 소리 · 글꼴

- **그림:** 지도, 캐릭터(모아·토토), 연구 시설, 학습 표본은 프로젝트용 AI 생성 이미지예요(기본 image_gen). 프롬프트와 원본 위치는 `docs/MAP_ASSET_PROMPT.md`, `docs/ART_GENERATION_20261024.md`, `assets/generated/*.json`에 남겼어요.
- **학습용 모형이라고 밝히기:** 관찰 그림은 실제 현미경 사진이 아니라 학습용 설명 모형이라고 설정의 저작권 고지와 각 활동의 '자료·관찰 조건'에 적었어요. 채집 장소와 조사 메모도 수업용 가상 사례라고 밝혀요.
- **같은 표본으로 비교하기:** 서로 다른 AI 그림을 같은 표본의 전후처럼 보여 주지 않으려고, 같은 원본 표본을 편집한 단계별 그림을 써요(빵·낙엽·반죽).
- **배경 음악:** 제작자가 본인 Suno Premier 플랜 계정으로 만든 가사 없는 2곡이에요. 메인테마는 지도·탐구, 엔딩테마는 결과 화면에서 나오고, 개념 영상이 재생될 때만 멈춰요.
- **효과음:** Kenney Interface Sounds 1.0(CC0)을 써요.
- **개념 영상:** 스테이지마다 12초 모션 그래픽 1개씩, 모두 5개예요. 프로젝트 그림을 써서 Pillow와 로컬 FFmpeg 스크립트(`scripts/render-concepts.py`)로 만들고 자막을 붙였어요. 영상 속 짧은 음은 자체 합성이에요.

## 4. 어려웠던 점과 해결

### 가로 태블릿 한 화면에 담기

- 한 화면에 중심 행동을 하나만 두었어요. 위 가운데는 질문, 가운데는 현상, 오른쪽은 지금 쓰는 도구, 아래는 주요 행동이에요.
- 터치 대상은 48px 이상, 주요 행동은 56px 이상으로 잡고, 한글은 어절 단위로 줄바꿈해요. 큰 글씨 모드에서는 내용을 자르지 않고 패널 안 스크롤을 허용해요.
- 리뷰에서 찾은 문제를 고쳤어요(`docs/REVIEW_FIX_20261025.md`).
  - 보고서 본문 일부가 폭 82px 열에 끼어 있었어요 → 그림과 본문을 나눠서 1024×768에서 본문 폭이 최소 643px가 됐어요.
  - 좁은 패널에서 코어 기록 카드가 넘쳤어요 → 한 열 요약과 내부 스크롤로 바꿨어요.
  - BIO 실패 안내가 비교 버튼 위에 겹쳤어요 → 패널 안에 공간과 스크롤을 확보했어요.
- 남은 것: 2026-10-25 점검에서 1280×720 화면에 14px·16px 글자가 남아 있었고(전자칠판 가시성), M4의 버튼 두 개가 패널 스크롤 아래에 있었어요.

### 저장된 기록 지키기

- 저장 원본이 비어 있거나, 미래 버전이거나, 구조가 깨졌을 때도 자동 저장과 새로고침이 원본을 덮지 않게 했어요.
- 오래 열어 둔 다른 창이 최신 기록을 덮어쓰려 하면 IndexedDB 트랜잭션에서 막고 화면에 알려 줘요.
- 교사용 시연 기록은 학생 기록과 따로 저장해요. 시연 기록을 초기화해도 학생 원본이 그대로인 것을 검사로 확인했어요.
- 다시 탐구할 때는 정상 제출한 활동만 도감에 반영해요. 초안이나 오답은 이전의 유효한 기록을 바꾸지 않고, 첫 보상은 두 번 주지 않아요.
- 소개 카드 PNG를 만들 때 학생이 저장한 원본 값은 고치지 않아요.

### 관찰 표시를 바르게 판정하기

- 리뷰 때 실제로 재현한 문제예요. 버섯 갓 위쪽 주름 `(0.50, 0.24)` 표시를 틀렸다고 했고, 깨끗한 빵 `(0.35, 0.48)`을 변화로 인정했어요.
- 버섯은 주름 윤곽을 따라 특징 영역을 정의하고 서로 다른 주름 4곳으로 검사했어요. 빵·낙엽은 각각 6개 전후 조합마다 실제 변화 영역(`src/observation-masks.json`)을 만들어서, 깨끗한 부분·배경·같은 시점은 거절해요.
- 확대·이동한 상태에서 그림과 판정이 어긋나던 것은, 원본 좌표와 화면 좌표의 변환을 그리기·터치·버튼 대안이 함께 쓰도록 맞췄어요. 틀린 표시를 더해도 이미 찾은 올바른 표시는 지우지 않아요.
- 판정 영역이 기준으로 삼는 원본 그림 11개는 해시로 검사해서(`scripts/observation-masks.mjs --check`), 그림이 바뀌면 바로 알 수 있어요.

### 예상과 실행 기록

실행한 뒤 예상만 바꿔도 완료되던 문제가 있었어요. 지금은 실행할 때의 예상·배치·연결·결과를 시도 기록으로 남기고, 새 예상에는 새 실행이 필요해요. 틀린 예상이어도 결과와 근거를 맞게 비교하면 완료돼요.

## 5. 아직 남은 것

- **실제 수업 적용:** 학생 파일럿을 하지 않았어요. 학습 전후 변화, 수업 시간, 다시 하고 싶은지는 확인하지 않았어요.
- **교육과정 원문 대조:** 성취기준 문구를 고시문 원본과 최종 대조하지 못했어요. 2026-10-25 점검에서 핵심 개념어(균사·포자·섬모 등)와 질병 사례가 없다는 지적이 나왔어요.
- **과학 자료 교과 검수:** 관찰 그림은 설명 모형이라서, 수업 배포 전에 자료·교과 검수가 필요해요.
- **실제 기기:** 실물 iPad·Android 태블릿, Safari, 한글 가상 키보드, 실제 프린터 출력, 교실 전자칠판 거리, 학교망과 30대 동시 접속, 배경 음악 음량은 직접 확인하지 못했어요. PC 브라우저의 화면 크기 흉내와 터치 이벤트로 확인한 범위예요.
- **오프라인:** 2026-10-25 점검 기준으로 서비스워커가 없어서 와이파이가 끊긴 상태에서 새로고침하면 다시 열리지 않았어요. 이어서 진행한 수정 결과는 기능향상기 마지막 절에 기록해요.
- **AI 생성 이미지 조건:** 상업 납품을 위해 생성 당시 계정·이용 조건을 담당자가 대조해야 해요.
- **게임성:** M3(세균의 단서)의 긴장감과 완주한 뒤 다시 열 이유가 약하다는 점검 결과가 있어요.
