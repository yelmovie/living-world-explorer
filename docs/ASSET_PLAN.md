### 조립 규격

- 작업대: 빈 dock 3개. 세 모듈의 받침 모양과 크기는 같다. 어느 빈 자리에도 놓을 수 있고 정답은 생물/작용·흐름 관계로 판정한다.
- 입력: 출력 연결구 1개. 작용: 입력·출력 연결구 각 1개. 결과: 입력 연결구 1개.
- 연결구 높이·직경·좌표축을 공통 규격으로 맞추고 GLB 후처리 때 실제 치수를 통일한다. 이미지 프롬프트만으로 치수 일치를 보장하지 않는다.
- 코어: 빈 카트리지 포트 5개. 관찰·비교·자료·영향·활용 라벨은 DOM 또는 런타임 표시다.
- 카트리지: 모델 1개를 5회 인스턴싱한다. 학생 기록의 썸네일은 런타임에 적용한다.
- 레버: 고정부와 손잡이/가동부를 분리하고 회전축을 지정한다. 다른 화면에서 같은 모델을 쓴다.
- 투명창·빛·액체·진행 입자·흐름선은 필요에 따라 런타임에서 만든다. 이미지에서 메시로 굳히지 않는다.

### GLB 인수 규격

| 자산 | 필요한 노드 또는 anchor |
|---|---|
| 작업대 | WorkbenchRoot, Dock_0, Dock_1, Dock_2 |
| 입력 모듈 | ModuleRoot, Port_Out |
| 작용 모듈 | ModuleRoot, Port_In, Port_Out |
| 결과 모듈 | ModuleRoot, Port_In, ResultPanel |
| 코어 | CoreRoot, Socket_Observation, Socket_Comparison, Socket_Data, Socket_Impact, Socket_Application |
| 레버 | LeverBase, LeverPivot, LeverHandle |
| 카트리지 | CartridgeRoot, DisplayPanel |

Y-up, 미터 단위의 공통 스케일, 바닥 중심 pivot, 외부 파일에 의존하지 않는 GLB를 기준으로 한다. 모델의 불필요한 뒷면·중복 재질을 줄이고 총량은 TRD의 장면 예산으로 확인한다. 레버의 회전 pivot과 DisplayPanel은 화면 동작에 맞게 후처리한다.

GLB 모델이 나오기 전 기능 개발에는 간단한 형상 모델을 사용할 수 있다. 사용자 시각 검증에서는 임시 형상을 실제 완성 에셋으로 보고하지 않는다.

모든 과학 자료에 sourceId, 출처 URL, 저작자, 사용 권한, visualType, 검수자/검수 상태를 기록한다. 연구 내용의 신뢰성과 이미지 재사용 권한은 각각 확인한다. 현재 이 묶음은 미확보·미검수 상태다.

과학 내용 검토 참고:
- 요구르트 사례의 세균 작용: [FAO Small Scale Dairy Farming Manual](https://www.fao.org/4/t1265e/t1265e02.htm). 학생용 문장은 “특정 세균의 작용을 발효 음식 만들기에 이용한다” 수준으로 쓴다.
- 분해 사례: [Microbiology Society Microbes and where to find them](https://microbiologysociety.org/publication/current-issue/why-microbiology-matters/article/microbes-and-where-to-find-them.html). 균류·세균의 분해 역할을 검토할 출발 자료다.
- 수중 먹이 관계: [Smithsonian Phytoplankton](https://ocean.si.edu/ocean-life/plankton/phytoplankton). 이 자료는 해양 식물성 플랑크톤의 먹이망 역할을 설명한다. 이를 연못의 특정 원생생물 사례에 그대로 대입하지 않고 교과에 맞는 대상 자료를 별도로 확정한다.

## 6 UI와 소리

UI는 공통 SVG로 홈, 이전, 소리 켜짐/꺼짐, 설정, 촬영, 기록 가방, 힌트, 실행·회전을 제작한다. 원본 화면 시안에 그려진 아이콘과 글자를 잘라 기능 버튼처럼 사용하지 않는다.

필수 소리는 배경음 1종과 클릭·관찰 촬영·기록 획득·연결·가동·복구 효과다. 사용 권한을 확인한 파일을 동봉한다. 음원이 없거나 재생이 막혀도 글자·모양 피드백으로 완주할 수 있게 한다.

## 7 제작 우선순위

1. 과학 자료 후보와 교과 검수 범위를 먼저 잡는다. 기능 개발용 도식과 실제 관찰 자료를 명시적으로 나눈다.
2. 지도 구도와 플레이어 픽셀 외형을 맞춘다. 2D 배경·모아 표정 컷을 준비한다.
3. 작업대·입력 모듈로 기준 재질을 확정하고 나머지 모듈을 맞춘다.
4. 코어·카트리지·레버를 제작하고 glTF anchor·가동부를 정리한다.
5. 목표 기기에서 화질·크기·터치·가림을 확인하고 파일을 최적화한다.

정지 장면 시안 2종은 배치 검토용 선택 산출물이며 게임 런타임 필수 자산은 아니다.

## 8 태블릿 탐구용 자료와 화면 개편

[탐구 경험 설계](INTERACTION_DESIGN.md)의 상호작용을 만들기 위한 추가 인수 항목이다. 모두 미확보/미제작/미검수이며 기능 구현 완료와 구분한다. 기존 이미지·3D 프롬프트 Page를 수정하거나 새 자료를 생성한 것은 아니다.

| 묶음 | 준비할 항목 | 검수/구현 조건 |
|---|---|---|
| M1 관찰 비교 | 표본별 충분한 해상도의 관찰 원본, 장비/배율, 특징 영역 | 기준 사진은 학생 촬영에서 생성. 가짜 확대 배율·보이지 않는 세부 합성 금지 |
| M2 재생 비교 | 동일 개체를 식별할 수 있는 검수 영상/시점 자료 또는 버전 고정된 교육용 이동 모형 | sourceId·trackId·표본 좌표·시점. 모형과 관측 자료 표기를 분리 |
| M3 주장 검토 | 6개 자료의 원문 구간/이미지 영역, 지원/불일치 주장 ID | 카드 제목·색으로 답이 노출되지 않도록 하고 자료 유형만으로 판정하지 않음 |
| M4 대표 시간 자료 | 같은 빵 표본 최소 4시점, 순서/실제 시간 정보, 정렬 변환, 유효한 복수 시점 쌍과 변화 영역 | 중간 상태 합성 금지. 시점 쌍은 한 근거, 생물/작용 자료는 별도 |
| M4 비교 자료 | 낙엽 분해의 전후 자료, 요구르트·물속 먹이 관계의 독립 근거 각 2개 이상 | 원생생물의 구체 대상은 교과 검수에서 확정 |
| M5 실행 | 검수된 예상/결과 선택지와 이유, 연결 누락·작용 불일치·결과 불일치·유효 흐름 표시 | 물리 제조 예측이 아닌 관계 모델. 텍스트·흐름·창 상태는 런타임 생성 |

시간 자료를 확보하지 못하면 개발 중에는 ‘설명용 도식’으로 표시하고 학생용 공개의 관찰자료 수용 기준은 미완료로 둔다. 생성형 이미지로 같은 표본의 실제 시간 관찰 자료를 만든 것처럼 표현하지 않는다.

기존 screen-mockups/chatgpt_full_015.png의 꿀벌·녹조·대나무와 완성된 분석 표는 새 M4 콘텐츠/배치 기준이 아니다. 014~015 시안은 책상·재질·색 분위기만 참고하고 중앙을 시간 관찰/학생 기록 비교로 다시 구성한다. 009 현미경 시안도 큰 캐릭터·제목 면적을 줄여 관찰 영역과 터치 도구를 확보한다.

3D 모델 7종은 유지한다. 입력·작용 모듈의 흐름 표시 영역과 결과 모듈의 ResultPanel은 런타임 내용이 잘 보이도록 재질/시점을 확인한다. 코어 카트리지 DisplayPanel은 실제 학생 썸네일을 읽을 수 있어야 한다. 슬롯 외형·색으로 올바른 생물 작용이 드러나지 않게 한다.

과학 자료 제작 우선순위는 M1 원본 → M4 시퀀스와 대응 영역 → M2 같은 개체의 재생 자료 → M3 원문 관계 → M5 사례 결과다. M4를 포함한 고해상도 자료는 미션 진입 시 로드하고 초기 필수 전송량을 늘리지 않는다. 실제 용량은 자료 확보 후 측정한다.
