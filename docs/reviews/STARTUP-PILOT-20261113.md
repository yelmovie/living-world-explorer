# 생명 코드 연구소 초기 로딩 시범 적용

첫 화면에 HTML 제목과 준비 안내를 먼저 표시하고, 앱이 준비되면 시작 버튼을 연결한다. 온실 배경과 캐릭터는 뒤에 표시한다. 새 탐험에서 영상이 끝나거나 건너뛴 뒤, 이야기 대화가 열린 동안 다음 목적지인 지도 코드만 준비한다. 이 요청은 지도 진입에서 재사용한다. 아직 열지 않은 탐구 화면은 앞서 받지 않는다.

지도가 실패하거나 늦으면 기존 해금 조건을 거쳐 탐구부터 시작할 수 있다. 실패 시 다시 불러오기도 제공한다. 첫 탐구가 조작 가능한 상태에 도달한 뒤 오프라인 캐시 준비를 시작한다.

| 항목 | 일반 연결, 전 → 후 | 제한망, 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 64 → 28 ms | 352 → 208 ms |
| 시작 버튼 준비 | 46 → 36 ms | 341 → 243 ms |
| 타이틀 로고 준비 | 60 → 36 ms | 965 → 406 ms |
| ‘탐험 지도로’ 입력 → 지도 렌더 | 121 → 71 ms | 1,350 → 926 ms |
| 지도에서 첫 활동 선택 → 조작 준비 | 52 → 53 ms | 892 → 892 ms |

같은 작업 트리의 변경 전후 Vite 프로덕션 빌드를 로컬에서 교대로 측정했다. Chrome 157, 1280×800, 각 조건·빌드마다 새 브라우저 문맥 5회 중앙값이다. HTTP 캐시·서비스워커는 성능 측정 동안 끄고, 제한망은 다운로드 10Mbps·지연 40ms·CPU 4배 감속을 적용했다. 인트로의 영상은 건너뛰고 이야기 대화에서 1.2초를 머문 뒤 지도에 들어갔다. 지도 시간에는 학생이 이야기를 보는 시간이 포함되지 않는다. 학교 태블릿과 운영 서버의 응답 시간은 이 측정에 포함되지 않는다.

- 정상 경로에서는 이야기 대화 중 지도 모듈이 요청됐고, 실제 지도 진입까지 같은 모듈의 요청은 한 번이었다. 첫 버튼 전에는 지도 엔진·영상 요청이 없었다.
- 데이터 절약 모드에서는 이야기 중 지도 요청이 없었고, 지도에 들어갈 때 한 번 요청됐다.
- 지도 모듈 차단 및 지연 상태에서 ‘탐구부터 시작하기’를 눌렀다. 첫 탐구에서 ‘죽은 나무 → 버섯 표본’, ‘축축해진 빵 → 곰팡이 표본’을 터치로 연결하고, 발견 기록 피드백을 확인했다. 지연을 풀어도 열어 둔 활동이 지도로 되돌아가지 않았다.
- 915×412 가로 화면에서 진입 JS 차단 후 ‘다시 열기’와 지도 모듈 차단 후 ‘지도 다시 불러오기’가 복구되는 것을 확인했다.
- 같은 가로 화면에서 Phaser 요청 자체를 차단하고 첫 활동에서 터치로 자료 하나를 연결해 진행이 1/2로 바뀌는 것을 확인했다.
- 첫 탐구가 열린 뒤 캐시 166개가 준비된 시점에 연결을 끊었다. 새로고침 후 첫 화면·지도·탐구 그림과 영상·배경 음악·안내 음성의 부분 응답을 확인했다. 지도 CSS의 배경 주소를 문서 기준으로 해석하게 고친 뒤에는 실패 요청이 없었다.
- 타입 검사, 프로덕션 빌드, 단위 검사 166개 통과. 운영 배포는 하지 않았다.

최종 성능 측정과 화면 캡처는 외장 SSD의 `.tmp/startup-pilot.RfARA3lb/final-evidence/`, 전체 오프라인 검사 결과는 같은 실행 폴더의 `offline-full.json`에 있다.
